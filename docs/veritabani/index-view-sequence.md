# Index, view, sequence ve identity

**Kapsam:** original wire v1 SQL. Bu nesneler farklı sorunları çözer; birini diğerinin yerine kullanmayın.

Index satırlara erişim yolunu, view okunan sütunların adlandırılmış görünümünü, sequence ve identity ise değer üretimini düzenler. Dördü de tablo tasarımına yardımcı olur; her biri bağımlılık ve bakım kararları doğurur.

## Index: sorguya uygun erişim

~~~sql
CREATE INDEX public.idx_urunler_id
ON public.urunler (id);
~~~

`WHERE id = :id` veya uygun aralık koşullarında index erişimi kullanılabilir. Original motorun belgesi, tek index sütununda equality/range erişimini açıkça tanımlar. Çok sütunlu index oluşturabilmek, bütün karmaşık filtrelerin o index'i kullanacağı anlamına gelmez. EXPLAIN ile gerçek planı inceleyin.

~~~sql
CREATE INDEX public.idx_urunler_ad_tr
ON public.urunler (ad) COLLATE turkish;
~~~

Index yazma maliyeti ve depolama kullanımı getirir. Her sütuna otomatik index eklemek yerine sık sorguların filtre ve sıralama ihtiyaçlarını ölçün. PK/UNIQUE kısıtını performans index'iyle eş anlamlı kabul etmeyin; kaynak testte PK'li tabloya ayrıca index eklenince sorgu erişim yolunun değiştiği görülür.

Index'i yeniden adlandırmak stable kimliğini korur:

~~~sql
ALTER INDEX public.idx_urunler_id RENAME TO idx_urunler_kimlik;
~~~

DROP INDEX satırları silmez; erişim yapısını kaldırır. Türkçe collation index'inin işletim sistemi sıralama sürümü değişmişse REINDEX gerekebilir. Bir index stale durumdayken ilgili yazmaların reddedilmesi veri düzeninin korunmasına yönelik davranıştır.

## View: kontrollü okuma tanımı

~~~sql
CREATE VIEW public.urun_listesi AS
SELECT id, ad, fiyat FROM public.urunler;
~~~

~~~sql
SELECT id, ad, fiyat
FROM public.urun_listesi
WHERE id = 101;
~~~

Belgelenen view kapsamı bir base table üzerinden named projection veya wildcard'tır. View'lar salt okunurdur. Laboratuvardaki bütün JOIN raporunu CREATE VIEW içine koyup desteklendiğini varsaymayın.

View oluşturulduğunda projeksiyondaki ordinal'ler sabit kalır. Temel tabloya yeni sütun eklenmesi var olan view'ın sütun listesini otomatik genişletmez. Bu davranış, `SELECT *` ile oluşturulmuş bir view için de anlaşılmalıdır.

View gizli bir yetki yükseltme aracı değildir. Invoker davranışında temel tablo SELECT yetkisi de kontrol edilir. View'ı kullanan bir API'nin veri görünürlüğünü tasarlarken hem view hem alt nesne yetkisini değerlendirin.

## Sequence ve DEFAULT

~~~sql
CREATE SEQUENCE public.destek_no;

CREATE TABLE public.destek_kayitlari (
    id BIGINT PRIMARY KEY DEFAULT NEXT VALUE FOR public.destek_no,
    konu TEXT NOT NULL
);

INSERT INTO public.destek_kayitlari (konu)
VALUES ('Teslimat bilgisi');
~~~

Sütun INSERT'te atlandığında sequence değeri alınır. Sequence kendi adı olan ayrı bir nesnedir ve DEFAULT bağımlılığı bulunduğu sürece rastgele kaldırılamaz. Aynı sequence'i farklı nesnelerde kullanmak mümkündür; bunun kimlik alanlarının anlamını karıştırmamasını sağlayın.

## Identity

~~~sql
CREATE TABLE public.olaylar (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    aciklama TEXT NOT NULL
);

INSERT INTO public.olaylar (aciklama)
VALUES ('Sipariş kaydedildi');
~~~

Identity tablonun sütununa bağlı sayaçtır. `BY DEFAULT` biçimi açık değer girilmesine izin verir. Belgelenen davranışta açık identity değeri sayacı ilerletmez. Örneğin elle yüksek kimlik girip daha sonraki otomatik üretimin onun üzerinden devam edeceğini varsaymayın.

Original motorda statement veya transaction rollback'i sequence/identity sayacını da geri alır. Başka veritabanlarının “sequence her durumda tüketilir” davranışını buraya taşımayın. Yine de dış sistemde yayınlanmış bir kimliği geri alınabilir sayaç değeriyle eşitlemek iş akışı problemi yaratabilir; kimliği işlem kalıcılaştıktan sonra paylaşın.

## Ne zaman hangisi?

| İhtiyaç | Nesne/karar |
| --- | --- |
| Sık kimlik aramasını hızlandırmak | Ayrı index ve plan doğrulama |
| Sabit sütun kümesini adlandırmak | Read-only view |
| Birden çok yerde paylaşılan sayaç | Sequence |
| Tabloda otomatik BIGINT üretmek | Identity |
| Tekrarlı veriyi engellemek | PK/UNIQUE constraint |
